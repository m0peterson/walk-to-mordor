# Карта

Главный экран: большая карта с зумом и прокруткой, поверх неё приложение рисует маршрут, пройденную часть, вехи и хоббитов. На самой картинке карты ничего этого нет (см. `image-prompts/map/world-map.md`).

## Почему тайлы

Карта 6144×6144 как один bitmap занимает около 150 МБ памяти, телефон её не потянет. Поэтому карта режется на тайлы 256×256 с несколькими уровнями детализации, и на экране только видимые тайлы нужного уровня.

## Библиотека

MapCompose (`ovh.plrapps:mapcompose`): Compose-библиотека для тайловых карт с маркерами, линиями (в том числе пунктирными) и жестами. Подходит почти один в один: координаты в долях 0..1, маркеры это обычные composable, линии рисуются по списку точек.

Решение подтверждается спайком T-301 на заглушке размером с финальную карту. Если спайк проваливается (тормозит, не хватает API, ломается на Robolectric), запасной вариант: `Telephoto` (`SubSamplingImage` + свой слой маркеров и линий поверх с пересчётом координат). Итог спайка записывается в ADR-007.

## Тайлы

- Скрипт `tools/map-tiles/make_tiles.py` (Python 3 + Pillow), запускается руками, результат коммитится.
- Вход: мастер-PNG любой квадратной или прямоугольной карты.
- Выход: `content/src/main/assets/map/tiles/{level}/{row}/{col}.webp` и `content/src/main/assets/map/meta.json`.
- Уровни в соглашении MapCompose: последний уровень это полное разрешение, каждый предыдущий в два раза меньше. Количество уровней такое, чтобы на самом мелком карта влезала примерно в один-два тайла.
- Крайние тайлы, которые не заполняются картой целиком, дополняются цветом пергамента до 256×256.
- WebP с качеством ~80. Скрипт печатает общее число тайлов и общий вес.

Заглушка до появления финальной карты: `image-prompts/map/layout-reference-clean.png`, растянутая до 6144×6144, чтобы проверять производительность в реальном размере. Финальная карта заменяет её тем же скриптом.

## Слои

Снизу вверх:

| Слой | Как выглядит | Данные |
|---|---|---|
| Тайлы | | `map/tiles` |
| Оставшийся маршрут | пунктир сепией, ~3 dp, 60% непрозрачности | `RouteGeometry.pathFrom(км маршрута)` |
| Пройденный маршрут | сплошная линия цвета сургуча `waxRed`, ~4 dp | `RouteGeometry.pathUntil(км маршрута)` |
| Малые вехи | маленькая чернильная точка | пройденные залиты, будущие полые |
| Большие вехи | значки из `image-prompts/map/map-markers.md`: печать (пройдена), флажок (следующая), чернильный кружок (впереди) | |
| Подписи | плашка с названием из `texts/*.json` | только у пройденных больших вех и у следующей, и только при зуме больше среднего |
| Хоббиты | жетон с хоббитом, поверх всего | `JourneyProgress.position` |

Если файлов значков ещё нет, те же формы рисуются векторно в Compose. Значок жетона заменяется кругом с инициалом в цвете чернил.

## Камера и жесты

- При открытии: центр на хоббитах, средний зум (видно вехи по соседству).
- Кнопка «К хоббитам» возвращает туда же.
- Минимальный зум: карта целиком на экране. Максимальный: 1 пиксель карты на 1 пиксель экрана (дальше апскейл становится заметен, см. заметки в `world-map.md`).
- Прокрутка ограничена краями карты.
- Поворот выключен.
- Тап по большой или малой вехе: `onWaypointClick(id)`. Тап по хоббитам: открыть нижнюю панель прогресса.

## Обновление

- Положение хоббитов и линии пересчитываются, когда меняется `JourneyProgress`. Хоббиты сдвигаются анимацией (~600 мс), камера не прыгает сама, если пользователь в этот момент смотрит другое место.
- Линии строятся из `RouteGeometry`, ничего не рисуется по пикселям вручную.

## Доступность

- У каждой вехи `contentDescription`: «Веха 7, Ривенделл, пройдена» / «следующая, через 120 км» / «впереди».
- Хоббиты: «Вы здесь: 812 км из 2 863».
- Кнопка «К хоббитам» с подписью.
- Карта не единственный способ узнать прогресс: всё то же есть текстом в панели прогресса.

## Производительность

- Не больше одного `MapState` на экран, создаётся во ViewModel (переживает поворот экрана).
- Подписи и маркеры: только для вех, а не для каждой точки `via`.
- Проверка в T-301 и T-302: на телефоне среднего класса прокрутка и зум без рывков, расход памяти записывается в PR.
