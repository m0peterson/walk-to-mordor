# T-302. Карта пути: маршрут, вехи, хоббиты

- **Этап:** M3
- **Модули:** `:feature:journey`
- **Зависит от:** T-301, T-102, T-103
- **Размер:** L
- **Прочитать:** [map.md](../architecture/map.md) целиком, [game-rules.md](../product/game-rules.md) раздел 6, [image-prompts/map/map-markers.md](../../image-prompts/map/map-markers.md)

## Зачем

Карта с хоббитами это то, ради чего приложение открывают. Она должна точно показывать, где пользователь, что пройдено и что впереди.

## Что сделать

1. **`JourneyMapController`**: класс, который живёт во ViewModel, держит `MapState` и умеет `update(snapshot: ProgressSnapshot, texts: RouteTexts)`. Его будет использовать `HomeViewModel` из T-402.
2. **`waypointMarkers(route, progress, visits): List<WaypointMarker>`**: чистая функция. Для каждой вехи: `id`, тип, номер, точка, состояние `PASSED` / `NEXT` / `AHEAD`. `PASSED`: км маршрута позади текущего положения. `NEXT`: первая впереди. Остальные `AHEAD`.
3. **Слои** ровно по таблице «Слои» в map.md:
   - пунктир оставшейся части и сплошная пройденная (через `RouteGeometry.pathFrom` и `pathUntil`);
   - малые вехи точками, большие значками из `markers/*.webp`, при отсутствии файлов векторные формы того же смысла;
   - подписи: только `PASSED` большие и `NEXT`, только когда масштаб больше порога (порог подобрать, записать константой);
   - хоббиты сверху, значок `markers/player.webp` или запасной круг.
4. **Камера:** старт с центром на хоббитах на среднем масштабе, кнопка «К хоббитам», ограничения из T-301. При обновлении позиции хоббиты сдвигаются анимацией ~600 мс; камера следует за ними, только если пользователь не трогал карту последние 10 секунд.
5. **Тапы:** по вехе `onWaypointClick(id)`, по хоббитам `onPlayerClick()`.
6. **Доступность:** `contentDescription` у вех и хоббитов по шаблонам из map.md, строки в `strings.xml` фичи с подстановкой названия из `RouteTexts`.
7. **Временная обвязка:** `HomeRoute` показывает эту карту на реальных данных через простой временный ViewModel (`ObserveProgress` + `ContentRepository`), без панели прогресса. Только в debug-сборке кнопка «+10 км»: добавляет корзину шагов в текущий час через `StepRepository`, чтобы проверять движение хоббитов без прогулки. T-402 заменит обвязку полноценным главным экраном, кнопку перенесёт в отладочное меню или удалит.

## Контракты

- Отдаёт `JourneyMapController`, composable `JourneyMap(controller, onWaypointClick, onPlayerClick, modifier)`, `waypointMarkers`.
- Берёт `ProgressSnapshot` (T-102), `RouteTexts` (T-103), пути к маркерам из `ContentPaths`.

## Чего не делать

- Не делать панель прогресса, баннеры, очередь карточек (T-402).
- Не считать положение в фиче: только `RouteGeometry` и `JourneyProgress`.
- Не показывать иллюстрации будущих вех.

## Критерии приёмки

- На тестовом маршруте `waypointMarkers` для положения посередине участка даёт правильные `PASSED`, `NEXT`, `AHEAD`; для положения ровно на вехе веха `PASSED`, следующая `NEXT`; после финиша все `PASSED`, `NEXT` нет.
- Хоббиты на экране там же, где `progress.position` (проверка в тесте контроллера через координаты маркера в `MapState` или эквивалент, которое даёт библиотека).
- Подписи появляются и исчезают на пороге масштаба.
- Без файлов маркеров всё рисуется векторными заглушками.

## Тесты

- `WaypointMarkersTest`: состояния вех во всех положениях из критериев.
- `JourneyMapControllerTest`: обновление позиции, линии, подписи, правило «камера не прыгает, если пользователь трогал карту».
- Roborazzi для отдельных composable маркеров и подписей (сама карта в Robolectric может не рендериться, тогда это отметить в PR).

## Ручная проверка

1. Начать путь, пройти немного, открыть: хоббиты у Бэг-Энда, сплошная линия от старта до них.
2. Нажать «+10 км» несколько раз: хоббиты сдвигаются вперёд с анимацией, линия пройденного удлиняется, на вехе значок меняется на печать.
3. Тап по вехе впереди: срабатывает обработчик (пока лог или тост).
