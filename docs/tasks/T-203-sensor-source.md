# T-203. Источник шагов: датчик

- **Этап:** M2
- **Модули:** `:core:steps`
- **Зависит от:** T-201 (интерфейсы, мультибиндинг, `StepAccessImpl`)
- **Размер:** M
- **Прочитать:** [steps.md](../architecture/steps.md) раздел «Датчик», ADR-004, ADR-005

## Зачем

На Android 9-13 без трекера Health Connect пуст, и без датчика у такого пользователя приложение просто не работает.

## Что сделать

1. **`SensorStateStore`**: отдельный DataStore `sensor_state.preferences_pb` с ключами из data.md. Исключается из резервной копии (правила бэкапа в T-502, но имя файла фиксируется здесь).
2. **`StepCounterReader`**: обёртка над `SensorManager`. Регистрирует слушатель `TYPE_STEP_COUNTER`, ждёт первое событие с таймаутом 10 с, снимает слушатель, возвращает значение или `null`. Интерфейс, чтобы подменять в тестах.
3. **`computeSensorDelta(...)`**: чистая функция по таблице из steps.md: первый замер, обычный, перезагрузка (по `BOOT_COUNT` или уменьшению счётчика), сбой датчика (больше 250 шагов в минуту с прошлого замера).
4. **`SensorStepSource`** (реализует `StepSource`, `type = SENSOR`):
   - `status()`: `UNSUPPORTED` без `FEATURE_SENSOR_STEP_COUNTER`; разрешение `ACTIVITY_RECOGNITION` на Android 10+ (на 9 считается выданным); `backgroundRead = true`;
   - `collect(from, to)`: замер, дельта, обновление `SensorStateStore`, результат `Delta(начало текущего локального часа, дельта)`. Нет события: `Delta(…, 0)`, база не трогается.
5. **`BootReceiver`** на `BOOT_COMPLETED`: `SyncScheduler.requestOnce(BOOT)`. Интерфейс из T-201, реализация из T-202, поэтому эта задача не зависит от того, смёржен ли T-202.
6. **`StepAccessImpl`**: заполнить ветку `SENSOR` в `status` и `recommendedSource`. Сброс `SensorStateStore` при `activate(SENSOR)`, чтобы первый замер стал новой базой.
7. **`access.ui`:** `rememberActivityRecognitionPermissionLauncher(onResult)`.
8. **Манифест:** `ACTIVITY_RECOGNITION`, `RECEIVE_BOOT_COMPLETED`, ресивер.
9. **Hilt-модуль `SensorModule`:** источник в мультибиндинг с ключом `SENSOR`, ридер, хранилище.

## Чего не делать

- Не держать слушатель датчика постоянно и не запускать foreground service.
- Не распределять дельту по нескольким часам (правило: вся дельта в текущий час).

## Критерии приёмки

- Каждая строка таблицы дельт из steps.md покрыта тестом.
- После `activate(SENSOR)` первая синхронизация даёт 0 шагов и сохраняет базу, вторая даёт разницу.
- Перезагрузка (новый `BOOT_COUNT`, счётчик 500) даёт дельту 500.
- Телефон без датчика: `status` `UNSUPPORTED`, `recommendedSource` не предлагает датчик.
- `sensor_state.preferences_pb` не совпадает по имени с файлом настроек.

## Тесты

- `SensorDeltaTest` на JVM: все случаи таблицы плюс граница 250 шагов в минуту.
- `SensorStepSourceTest` с фейковым ридером и `MutableClock`.
- `StepAccessImplTest` дополнить ветками датчика.

## Ручная проверка

1. Телефон без Health Connect или с отказом: выбрать датчик, пройти 200 шагов, открыть приложение, шаги видны (пока на заглушке, например в логе или временном тексте).
2. Перезагрузить телефон, пройти 100 шагов, открыть: шаги до перезагрузки сохранились, новые добавились.
