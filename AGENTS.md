# Правила для агентов

Этот файл читает каждый агент, который пишет код в этом репозитории. Он короче документации и главнее её в вопросах процесса. В вопросах продукта и архитектуры главнее документы из `docs/`.

## Что это за проект

Android-шагомер: реальные шаги двигают двух хоббитов по карте Средиземья от Шира до Роковой горы за выбранный пользователем срок. Офлайн, без сервера, без доступа в интернет.

Прочитать перед любой задачей:

1. [docs/product/prd.md](docs/product/prd.md): что строим и для кого.
2. [docs/architecture/overview.md](docs/architecture/overview.md): модули, контракты, правила зависимостей.
3. Файл своей задачи в [docs/tasks/](docs/tasks/README.md) и все документы, перечисленные в нём.

Словарь: **веха** = `Waypoint` (большая `MAJOR` или малая `MINOR`), **путь** = `Journey`, **этап** = M0..M5 в роадмапе. Слово `Milestone` в коде не используем, чтобы не путать с этапами.

## Золотые правила

1. **Одна задача, один PR.** Делай то, что написано в разделе «Что сделать», и не делай того, что в «Чего не делать». Нашёл проблему вне задачи: опиши её в PR в разделе «Замечено по пути», не чини.
2. **Контракты не меняются молча.** Сигнатуры из `overview.md`, схема из `data.md`, формат `route.json`: если их нужно поменять, поменяй документ в том же PR и вынеси это первым пунктом в описание PR.
3. **Правила игры только в `:core:domain`.** ViewModel и UI форматируют, но не считают план, статус, вехи и километры.
4. **Средиземье только в `:content`.** Ни одного названия места, имени персонажа или цитаты в коде и строках других модулей. В тестах других модулей используй тестовый маршрут из `:core:testing`.
5. **Никакого `INTERNET`.** Не добавляй библиотеки, которые его требуют (сетевые модули Coil, Firebase, аналитика, отчёты о падениях).
6. **Время только через `Clock`.** `Instant.now()`, `LocalDate.now()`, `System.currentTimeMillis()` запрещены вне провайдера `Clock`.
7. **Версии только в `gradle/libs.versions.toml`.** Новая библиотека: строка в каталоге и абзац в PR, зачем она и почему не хватает существующих.
8. **Не гадай с API.** Health Connect, MapCompose, Roborazzi, Glance меняются. Сверяйся с документацией той версии, что в каталоге. Если в документации и в ТЗ разные имена, прав код по документации, а в PR это отмечено.
9. **Не выдумывай требования.** Если ТЗ молчит, выбери самый простой вариант, который не противоречит документам, и запиши выбор в PR в раздел «Решения по ходу».

## Модули и границы

Схема и правила зависимостей: [overview.md](docs/architecture/overview.md#модули). Коротко:

- фичи (`:feature:*`) зависят только от `:core:domain`, `:core:designsystem`, `:content`. Исключение: онбординг и настройки берут из `:core:steps` пакет `access.ui` (запуск диалогов разрешений);
- `:core:domain` это чистый Kotlin/JVM, без Android;
- `:core:steps` и `:core:notifications` зависят только от `:core:domain`;
- Hilt-биндинги реализаций живут в модуле реализации, `:app` их только подключает;
- **у каждой задачи свой Hilt-модуль** (`HealthConnectModule`, `SensorModule`, `SyncModule`...). Не дописывай биндинги в чужой файл: так параллельные задачи не конфликтуют.

## Код

- Kotlin, стиль ktlint (официальный), проверяет Spotless.
- Пакет `io.github.m0peterson.longwalk.<модуль>`.
- UI: Compose, Material 3, компоненты и цвета только из `:core:designsystem`. Цвета и размеры не хардкодятся в фичах.
- Экран = `XxxScreen` (stateless, принимает `UiState` и лямбды) + `XxxRoute` (берёт ViewModel, собирает состояние) + `XxxViewModel`.
- `UiState` это `data class` или `sealed interface`, неизменяемый. ViewModel отдаёт `StateFlow<UiState>` и принимает события методами.
- Корутины: диспетчеры внедряются (`@IoDispatcher`), `GlobalScope` запрещён, в ViewModel `viewModelScope`.
- Строки: в `values/strings.xml` английский, в `values-ru/strings.xml` русский. Обе версии в том же PR. Числа и даты через локаль. Склонения через `plurals`.
- Доступность: у всех значимых картинок и иконок `contentDescription`, у декоративных `null`. Размер нажимаемых элементов от 48 dp. Текст выдерживает увеличенный шрифт (проверяется скриншотом с `fontScale = 1.5`).
- Комментарии только там, где неочевидно «почему». Публичные классы домена с KDoc на одну-две строки.
- `!!` запрещено вне тестов.

## Тесты

Что именно тестировать, написано в каждой задаче. Общие правила:

- Фейки вместо моков. Фейки репозиториев, источников шагов и часов живут в `:core:testing`. Нужен новый фейк: добавь его туда.
- Домен: JUnit на JVM. Каждое правило из `game-rules.md`, которое реализует задача, это минимум один тест с понятным именем: `` `behind when delta is minus one day` ``.
- ViewModel: Turbine, `MainDispatcherRule`, фейки.
- Экраны: Roborazzi на Robolectric (`@GraphicsMode(NATIVE)`), по скриншоту на каждое состояние из ТЗ, для `ru` и `en`. Эталонные скриншоты коммитятся в том же PR.
- Тест, который зависит от текущего времени или часового пояса, это баг. Используй `MutableClock` из `:core:testing`.

## Команды

```bash
scripts/setup-android-sdk.sh        # один раз в новом окружении (создаёт T-001)
./gradlew assembleDebug
./gradlew testDebugUnitTest         # все unit-тесты, включая Robolectric
./gradlew :core:domain:test         # быстрые тесты домена
./gradlew spotlessApply             # поправить стиль
./gradlew spotlessCheck lintDebug
./gradlew recordRoborazziDebug      # записать эталонные скриншоты
./gradlew verifyRoborazziDebug      # сверить скриншоты
scripts/check-no-internet.sh        # нет ли INTERNET в итоговом манифесте (создаёт T-002)
```

Перед открытием PR всё это должно проходить: `spotlessCheck lintDebug testDebugUnitTest verifyRoborazziDebug assembleDebug` и `check-no-internet.sh`.

Эмулятора в окружении агента нет. То, что можно проверить только на телефоне, перечисли в PR в разделе «Ручная проверка» по шагам, владелец проверит.

## Git и PR

- Ветка от `main`: `task/T-XXX-short-name`.
- Коммиты на английском, в повелительном наклонении: `Add route geometry interpolation`. Один логический шаг на коммит.
- PR: заголовок `T-XXX: <название задачи>`, описание по шаблону `.github/pull_request_template.md`.
- В PR приложи скриншоты экранов (из Roborazzi), если задача про UI.
- Не трогай `docs/roadmap.md` и статусы задач: статус живёт в issue и PR, иначе параллельные PR конфликтуют.
- Не добавляй файлы картинок, которых нет в задаче. Картинки кладёт владелец.

## Готово, когда

- [ ] сделано всё из «Что сделать» и выполнены все «Критерии приёмки» задачи;
- [ ] тесты из раздела «Тесты» задачи написаны и проходят;
- [ ] все команды из раздела «Команды» проходят локально;
- [ ] строки на двух языках;
- [ ] в коде вне `:content` нет названий из Средиземья;
- [ ] если менялись контракты или схема, документы обновлены в этом PR;
- [ ] PR заполнен по шаблону, включая «Ручная проверка» и «Решения по ходу».

## Если застрял

- ТЗ противоречит документам: правы документы в `docs/architecture` и `docs/product`, отметь противоречие в PR.
- Библиотека не умеет того, что нужно: не обходи это хаком. Опиши в PR, предложи 1-2 варианта, сделай тот, что меньше меняет контракты.
- Не хватает данных (нет картинки, нет текста): используй заглушку, как описано в `content-pack.md`.
